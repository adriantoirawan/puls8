## 🚀 Advanced Stretch Goals (The "WOW" Factor)

We didn't just build the MVP—we engineered a robust architecture utilizing advanced patterns.

### [STR-1-PRG-Pattern] Post/Redirect/Get Flow
- **Location**: `controllers/authController.js` (inside `postRegister` and `getRegister`)
- **How & Why**: Instead of directly `res.render()`ing an error view when a POST request (like registration) fails validation, the server safely redirects (`res.redirect`) back to a GET route passing the error in the URL query (`?error=...`).
- **Benefit**: This completely prevents the dreaded "Confirm Form Resubmission" browser warning if a user refreshes the page after an error. It strictly separates mutating requests (POST) from idempotent views (GET), a staple of mature web apps.

### [STR-2-Phase-Locking] Strict Server-Side Scoping
- **Location**: `controllers/instructorController.js` (inside `getGrade`, `resolvePhase`, etc.)
- **How & Why**: We don't rely purely on the UI to hide data. Before an instructor can grade a student or move them up, the backend explicitly queries data locked to that student's `phaseLevel`.
- **Benefit**: This ensures a student in Phase 0 can never be accidentally evaluated using Phase 2 grading rubrics. It isolates the relational models on the backend.

### [STR-4-Empty-State-UI] Dynamic Dashboard Fallbacks
- **Location**: `views/instructor/dashboard.ejs`
- **How & Why**: We injected inline EJS JS (`classData.some(...)`) that loops over the eager-loaded datasets to verify if the search filter actually yielded students. If the filtered array is completely empty, it renders an informative blue alert containing the exact term they searched for.
- **Benefit**: Greatly improves UX. Instead of leaving the user staring at an empty card or a blank screen, the UI proactively communicates the system state.
